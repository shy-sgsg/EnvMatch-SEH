# Codex 科研任务执行协议

## 文件优先级

1. `docs/RESEARCH_CHARTER.md`：研究主题、科学问题、总体目标、长期路线和成功标准；任何较低层文件不得推翻它。
2. `docs/governance/`：科研执行、审查、总纲审批和阶段门规则。
3. `docs/RESEARCH_PLAN.md`、`docs/METHODOLOGY.md`、`docs/DATA_REQUIREMENTS.md`：实施方案和数据约束。
4. `README.md`、`docs/WORKFLOW.md`：用户操作和任务流程。
5. 开发日志、数据审计、运行报告与实验记录：动态事实，不得自动覆盖总纲。

## 每轮任务开始

1. 阅读 `AGENTS.md`，确认本项目约束；随后完整阅读当前 Git 版本的 `docs/RESEARCH_CHARTER.md`。
2. 阅读 README、当前阶段门、对应研究方案/方法、开发日志、决策记录和相关结果。
3. 检查 Git 分支、HEAD、远端、工作区差异和数据目录；不覆盖用户已有文件或成果。
4. 说明当前任务推动哪些科学问题、属于哪个阶段门、所需证据及停止条件。
5. 对科研任务先核对数据和方法适用性；不得只因现有 CLI 能运行就默认方法适合真实数据。

## 执行与阶段控制

- 严格按 G0–G5 阶段门执行。某阶段未通过时，停止依赖该阶段的分析；继续完成不依赖问题数据的检查。
- `FORMAL` 模式的健康指标不得进入环境变量筛选、聚类、匹配阈值、配对或样本选择；G4 未通过和设计未锁定时不得开展正式健康回归。经明确授权的 `EXPLORATORY_ORACLE` 可进行结果导向搜索，但须标记并单独保存。
- R/K/LS/C/P 不进入环境距离。正式模式的相似性和匹配阈值不得根据健康结果调参；Oracle 模式允许结果导向优化，并须记录筛选指标、目标、试验数、样本量及空间验证差距。
- 按用户指示使用已有实际侵蚀 Aa，不重建或验证 RUSLE 因子乘积；只做运行所需的可读性、范围、缺失及空间对齐检查。非关键元数据缺失须披露，不自动阻止已授权的 Oracle 探索。
- `FORMAL` 与 `EXPLORATORY_ORACLE` 使用不同实验标识和输出根目录。Oracle 结果不得写入 `outputs/run_<id>/` 或作为正式科学证据。
- 实施层方法可根据数据证据调整，但须说明原因、影响、证据并记入 `DECISIONS.md`。改变总纲级目标、问题或路线时，先提交总纲修改申请并等待用户明确批准。
- 原始数据只读；派生数据写入 `data/interim/` 或 `data/processed/`；原始数据、敏感信息和大型中间栅格不得提交或上传。
- 输出必须关联输入逻辑名/路径、提交 SHA、配置、软件版本和主要计算过程。不存在的数据和字段保留缺失，不得推测填造。

## 任务结束

记录实际完成阶段、PASS/WARNING/BLOCKED 状态、统计证据、未解决事项、对总体目标的贡献及下一步。提交前检查测试、差异、数据排除规则和总纲未改动。科研阶段产出 `docs/templates/CHATGPT_REVIEW_REQUEST.md` 格式的固定提交审查材料；Codex 不代替用户向外发送审查请求。
